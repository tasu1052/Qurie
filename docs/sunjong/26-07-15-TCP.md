# TCP 핵심 개념 요약 정리 (대화 내용 기반)

이 문서는 TCP에 대한 우리의 논의를 주제별로 정리한 요약본입니다. TCP의 기본 연결 과정부터 정교한 혼잡 제어 알고리즘, 그리고 공평성 문제까지의 내용을 다룹니다.

---

## 1. TCP 연결의 시작, 유지, 그리고 상태 관리

TCP 통신은 단순히 데이터를 보내는 것뿐만 아니라, 연결을 설정하고 유지하며 사용자의 상태를 관리하는 과정이 포함됩니다.

### 1.1. 3-Way Handshake: 첫 만남의 규칙

- **첫 SYN 패킷의 순서 번호(ISN)는 무엇인가?**
    - 과거와 달리, 현재는 보안상의 이유(TCP Hijacking 방지)로 **완전한 난수(Random Number)**를 사용합니다.

### 1.2. 연결의 수명: Keep-Alive와 타임아웃

- **연결은 언제까지 유지되는가?**
    - **HTTP Keep-Alive (지속적 연결):** 하나의 TCP 연결을 재사용하여 여러 요청(HTML, CSS, 이미지 등)을 처리함으로써 효율을 높입니다.
    - **서버 타임아웃:** 연결 후 아무런 요청이 없으면, 서버에 설정된 `Keep-Alive-Timeout`(보통 5~75초)이 지나면 서버가 먼저 연결을 종료합니다.
    - **사용자의 행동:** 사용자가 브라우저 탭을 닫으면, 브라우저가 즉시 `FIN` 패킷을 보내 연결을 능동적으로 종료합니다.
- **Keep-Alive Timeout을 너무 길게 설정하면?**
    - '쉬는 연결'이 서버 자원을 계속 점유하여 **커넥션 풀 고갈(Connection Pool Exhaustion)** 현상이 발생합니다. 이로 인해 새로운 사용자가 접속하지 못하는 서비스 장애가 발생할 수 있습니다. ('커넥션이 마르는 현상')

### 1.3. 상태 관리: 장바구니와 TCP는 무관하다

- **장바구니 정보는 어떻게 유지되는가?**
    - 장바구니와 같은 사용자의 '상태(State)'는 TCP 연결에 저장되지 않습니다. TCP 연결은 일시적인 '통로'일 뿐입니다.
    - 상태는 서버 측의 **세션(Session)**에 저장되며, 사용자의 브라우저에 저장된 **쿠키(Cookie)**의 Session ID를 통해 식별됩니다. 따라서 TCP 연결이 끊어져도 장바구니는 안전하게 유지됩니다.

## 2. TCP 혼잡 제어: 똑똑하게 속도 조절하기

TCP의 핵심 기능으로, 네트워크 상황에 맞춰 데이터 전송량을 조절하여 전체 네트워크의 안정을 꾀합니다.

### 2.1. 기본 철학

- **종단 간(End-to-End) 제어:** 네트워크 중간의 라우터가 아닌, 통신의 양 끝단(송신/수신 컴퓨터의 TCP 스택)이 주체가 되어 능동적으로 혼잡을 제어합니다.
- **혼잡 신호:** 전통적으로 **패킷 손실(Packet Loss)**을 혼잡의 신호로 간주합니다.

### 2.2. 전통적인 방식: TCP Reno (AIMD)

느린 시작(Slow Start)과 혼잡 회피(Congestion Avoidance) 두 단계를 통해 `cwnd`(혼잡 윈도우)를 조절하는 **AIMD(Additive Increase / Multiplicative Decrease)** 방식을 사용합니다.

| 구분 | **심각한 혼잡 (타임아웃)** | **가벼운 혼잡 (3개의 중복 ACK)** |
| --- | --- | --- |
| **상황 인식** | 네트워크 마비 가능성 | 패킷 하나만 유실됨 |
| **`ssthresh` 변경** | `cwnd`의 절반으로 감소 | `cwnd`의 절반으로 감소 |
| **`cwnd` 변경** | **1 MSS**로 리셋 | **`ssthresh` 값**으로 감소 (1로 안 감) |
| **다음 단계** | **Slow Start** 부터 다시 시작 | **혼잡 회피** 부터 바로 시작 |
| **메커니즘** | 기본 동작 | **빠른 회복 (Fast Recovery)** |

### 2.3. 진보된 혼잡 제어 알고리즘

| 알고리즘 | 핵심 특징 | 장점 |
| --- | --- | --- |
| **TCP CUBIC** | **3차 함수(Cubic Function)** 기반으로 `cwnd` 조절 | **고속/장거리 환경**에 최적화, **RTT 독립적**이라 공평성이 높음 (현재 OS 표준) |
| **TCP Vegas** | **지연(Delay) 기반** 제어. `BaseRTT`와 현재 RTT를 비교하여 혼잡 **'예측'** | 패킷 손실이 발생하기 전에 미리 속도를 조절하여 안정적이고 효율적 |
| **ECN** | **명시적 혼잡 통보**. 라우터가 혼잡 예상 시 패킷에 **'ECN 비트'**를 표시 | 패킷 손실 없이 혼잡 신호를 주고받아 불필요한 재전송을 줄임 (선제적 대응) |

## 3. TCP 공평성 (Fairness) 문제

- **한 사용자가 병렬 연결을 사용하면?**
    - **결론: 공평성은 보장되지 않습니다.** 병렬 연결을 많이 여는 사용자가 훨씬 더 큰 전송률을 독점하게 됩니다.
- **이유는?**
    - TCP는 **'연결(Connection)' 단위로 공평성을 추구**할 뿐, 그 연결의 **'소유자(User)'**가 누구인지는 고려하지 않습니다. 10개의 연결은 1개의 연결보다 10배의 자원을 할당받으려는 경향이 있습니다.
- **현실의 예시와 대응 방안**
    - **예시:** 웹 브라우저(속도 향상), 다운로드 가속기(대역폭 독점)
    - **대응:** TCP 자체보다는 서버/네트워크단에서 **IP당 연결 수 제한**이나 **공평 큐잉(Fair Queuing)**과 같은 기술로 대응합니다.
