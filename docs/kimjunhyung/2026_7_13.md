## 1. 기본 재료: 임베딩과 벡터스토어

### 임베딩 (Embedding)

- 문장(또는 코드)을 **숫자 배열(벡터)**로 바꾸는 것. 임베딩 모델이 수행.
- 핵심 성질: **뜻이 비슷하면 벡터가 가깝다.**
- 수학적으로: 텍스트를 고차원 공간(예: 1536차원)의 점으로 매핑하는데,
  의미적 유사도가 공간상 거리(코사인 유사도)로 보존됨.
  → "의미"라는 애매한 것이 **내적 계산 가능한 기하 문제**로 바뀜.

```
"강아지가 귀엽다"        → [0.23, -0.81, 0.44, ...]
"댕댕이 너무 사랑스러움"  → [0.25, -0.79, 0.41, ...]  ← 가까움
"오늘 주가가 폭락했다"    → [-0.67, 0.32, -0.91, ...] ← 멂
```

### 벡터스토어 (Vector Store)

- **벡터를 저장하고, 주어진 벡터와 가까운 것을 빨리 찾아주는 특화 DB.** 그게 전부.
- 일반 DB와의 차이:

| | 일반 DB (MySQL) | 벡터스토어 |
|---|---|---|
| 질의 방식 | 정확 일치 ("id=5", "제목에 X 포함") | 유사도 ("이 벡터와 가장 가까운 top-k") |
| 예시 | MySQL, PostgreSQL | Chroma, Qdrant, FAISS, pgvector |

- **pgvector** = PostgreSQL을 벡터스토어로도 쓰게 해주는 확장 (PostgreSQL 전용, MySQL 불가).
- MySQL은 9.0부터 VECTOR 타입은 있지만 거리 계산 함수가 무료 버전에 없음
  → 사실상 MySQL로는 벡터 검색 불가.
- **규모가 작으면 벡터스토어 자체가 불필요.**
  수천 개 규모면 벡터를 일반 DB에 저장하고 numpy로 코사인 유사도 전수 계산 (밀리초).
  벡터스토어의 존재 이유는 "수백만 개 중에서 빨리" 찾는 것.

## 2. RAG (Retrieval-Augmented Generation)

### 정의

LLM이 모르는 지식(사내 문서, 최신 자료 등)을 **외부에서 검색해 프롬프트에 붙여주고** 답하게 하는 기법.

- **R**etrieval: 관련 조각을 꺼내서
- **A**ugmented: 프롬프트에 붙여서
- **G**eneration: 답변 생성

### 왜 필요한가 (2가지 이유)

1. 모델이 모르는 내용이라서 (학습 데이터에 없는 문서)
2. 통째로 컨텍스트에 못 넣어서 (문서가 너무 큼)

### 사전 준비 파이프라인 (색인 만들기)

```
문서 로드 → 청킹(쪼개기) → 임베딩 → 벡터스토어 저장
```

이 전체가 **"나중에 질문 받았을 때 관련 대목만 빠르게 꺼내 프롬프트에 붙이기 위한 사전 준비"**.
도서관에 책 꽂으며 색인 카드 만드는 것과 같음.
튜토리얼의 예제 문서(블로그 글 등)는 MNIST/붓꽃 같은 샘플 데이터일 뿐 — 실전에선 각자의 데이터가 들어감.

### 질의 시점 흐름

```
질문 → 임베딩 → 벡터스토어에서 가까운 조각 top-k 검색
     → 조각들을 프롬프트에 끼워넣음 → LLM이 그 텍스트를 근거로 답변
```

### 핵심 부품 개념

**Document (LangChain)**
- str이 아니라 **str을 담은 상자**. 속성 딱 2개:
  - `page_content` (str) — 본문
  - `metadata` (dict) — 출처 등 꼬리표
- metadata가 핵심: 쪼개져서 검색된 조각이 "어느 문서에서 왔는지" 추적 가능.
  Spring의 DTO 같은 역할 — 계층 사이를 오가는 표준 데이터 형식.
- 분할기·임베딩·벡터스토어가 전부 `list[Document]` 입출력으로 통일 → 부품을 레고처럼 교체 가능.

**청킹 (Chunking)**
- 긴 문서를 작은 조각으로 자르는 것. 이유: **검색 정밀도.**
  5만 자를 벡터 하나로 만들면 "문서 전체의 평균 의미"가 되어 핀포인트 검색 불가.
- `RecursiveCharacterTextSplitter`: 문단 → 문장 → 공백 → 글자 순으로
  **의미 덩어리를 최대한 안 깨면서** 크기 제한을 맞춤.
- `chunk_size`: 조각 크기 (토큰 기준이 안전 — LLM 제한이 토큰 단위라서, `from_tiktoken_encoder`)
- `chunk_overlap`: 옆 조각과 겹치는 양. 경계에 걸린 문장의 문맥 유실을 막는 보험.
- 실무 통상값: 500~1000 토큰, 10~20% 겹침.

## 3. Agentic RAG (2026 트렌드)

### 고정 파이프라인 vs 에이전트

**기존 RAG (2023~2025)**: 질문이 뭐든 무조건 검색 → top-k → 생성. 파이프라인 고정.
- 문제: "안녕하세요"에도 벡터스토어를 뒤짐. 검색을 건너뛸 수 없음.

**Agentic RAG (2026~)**: 검색이 고정 단계가 아니라 **LLM이 쓸지 말지 결정하는 도구**.

```
질문 → LLM 판단
        ├─ "문서 봐야겠네" → 검색 도구 호출 → 결과 채점 → 부족하면 질문 재작성 후 재검색
        └─ "그냥 답하면 되네" → 바로 답변
```

- 계획(planning) → 검색 → 비판(reflection) → 재작성 → 확신이 들 때까지 루프.
- 4대 에이전트 디자인 패턴: **reflection, planning, tool use, multi-agent collaboration**
  (arXiv 2501.09136 "Agentic RAG: A Survey")

### 공부 자료

1. LangChain 공식: docs.langchain.com/oss/python/langgraph/agentic-rag
2. 서베이 논문: arxiv.org/abs/2501.09136 (2장 + 그림 위주로)
3. Anthropic "Building Effective Agents" — 워크플로 vs 에이전트 멘탈 모델

## 4. LangChain vs LangGraph

**비유: LangChain은 레고 블록, LangGraph는 조립 설계도.**

| | LangChain | LangGraph |
|---|---|---|
| 역할 | LLM 앱 부품 (호출, 프롬프트, 파싱, 벡터스토어) | 흐름 제어 (분기, 루프, 상태 관리) |
| 흐름 | 일직선 체인 (A→B→C) | 그래프 (분기, 루프, 되돌아가기) |

- 체인의 한계 = 한 방향. "조건 분기"와 "뒤로 돌아가는 루프"가 필요한 순간 LangGraph.
- LangGraph는 LangChain 위에 만들어졌지만, 노드는 그냥 Python 함수
  → 안에서 LangChain을 쓰든 OpenAI 클라이언트를 직접 쓰든 무관.

### LangGraph 핵심 개념 4개

1. **State** — 노드들이 공유하는 데이터 가방 (TypedDict).
   노드는 상태 전체가 아니라 **바꿀 필드만 dict로 반환** → LangGraph가 병합.
2. **Node** — 작업 단계. 그냥 Python 함수.
3. **Edge** — 다음에 갈 곳. `add_edge("A", "B")` = 고정 연결.
   `add_edge("refine", "generate")` 한 줄이 루프의 전부.
4. **Conditional Edge** — 갈림길. 상태를 보고 **다음 노드 이름을 문자열로 반환**하는 함수.

```python
def route_after_judge(state) -> str:
    if passed: return "store"
    if state["retry_count"] >= MAX: return "discard"
    return "refine"
```

### 환경 설정 관련

- 튜토리얼의 `_set_env("OPENAI_API_KEY")` = API 키를 환경변수에 넣는 것.
  LangChain 모델 클래스가 정해진 이름의 환경변수를 자동으로 찾아 씀.
- `getpass` = input()인데 화면에 안 보이게 입력 (비밀값 노출 방지 관례).
- 외부 호환 API로 치환 시: 키 + `base_url` 교체.
  OpenAI 호환(`/v1/chat/completions`) 여부와 `response_format={"type": "json_object"}` 지원 여부 확인 필요.

## 5. 용어 사전 (빠른 참조)

| 용어 | 한 줄 정의 |
|---|---|
| 임베딩 | 텍스트 → 의미가 거리로 보존되는 벡터 |
| 벡터스토어 | 가까운 벡터를 빨리 찾아주는 특화 DB |
| RAG | 검색한 조각을 프롬프트에 붙여 답하게 하는 기법 |
| Agentic RAG | 검색 여부·전략을 LLM이 스스로 결정하며 루프 도는 RAG |
| 청킹 | 검색 정밀도를 위해 문서를 조각으로 자르기 |
| Document | page_content(str) + metadata(dict) 표준 상자 |
| Self-Refine | 생성→평가→피드백 반영 재생성 루프 (학계 용어) |
| Evaluator-Optimizer | 같은 패턴의 Anthropic 공식 명칭 |
| LLM-as-a-Judge | LLM이 다른 LLM 출력을 채점하는 패턴 |
| 블라인드 풀이 | 정답을 가리고 독립 모델이 풀게 하는 검증법 |
| State/Node/Edge | LangGraph의 데이터 가방 / 작업 함수 / 연결선 |
| tiktoken | OpenAI 토크나이저. 청크 크기를 토큰 단위로 재는 자 |
