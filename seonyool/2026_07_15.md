## 1. TypeScript 도입 배경 (Why TypeScript?)

JavaScript는 동적 타입(Dynamic Type) 언어로, 코드가 실행되는 런타임(Runtime) 시점에 변수의 타입이 결정됩니다. 이는 유연하다는 장점이 있지만, 브라우저에서 실행 중에 예상치 못한 타입 에러(예: `Cannot read properties of undefined`)가 발생하여 애플리케이션이 비정상 종료되는 원인이 됩니다.

TypeScript는 JavaScript에 정적 타입(Static Type) 시스템을 도입한 상위 집합(Superset) 언어입니다.
* **컴파일 시점 에러 감지:** 코드가 브라우저에 배포되기 전, 개발 도구(IDE) 단계에서 타입 불일치와 오타를 즉시 감지하여 런타임 에러를 사전에 방지합니다.
* **개발 생산성 및 자동 완성:** 외부 라이브러리나 서버에서 받아오는 데이터(예: Stream Video SDK의 `StreamVideoParticipant` 객체 등)의 명세를 에디터에서 바로 확인하고 안전하게 참조할 수 있습니다.

## 2. TypeScript 핵심 문법 정리

### ① 기본 타입 및 타입 추론 (Type Inference)
TypeScript에서는 변수명 뒤에 `: type`을 명시하여 변수의 타입을 한정합니다. 하지만 할당된 값을 기반으로 TypeScript가 타입을 스스로 판단하는 '타입 추론' 기능 덕분에 모든 곳에 타입을 수동으로 선언할 필요는 없습니다.

```typescript
// 명시적 타입 지정
let userName: string = "Seonyool";
let age: number = 25;
let isDeveloper: boolean = true;

// 타입 추론 (TS가 자동으로 string 타입으로 판단)
let currentFramework = "React"; 
// currentFramework = 2026; // ❌ 에러 발생: 'number' 형식은 'string' 형식에 할당할 수 없습니다.

// 배열 및 튜플
let scores: number[] = [90, 85, 100];
let userTuple: [string, number] = ["id_val", 101]; // 요소의 개수와 타입 순서가 고정된 배열

```

### ② Interface와 Type Alias (객체 정의 구조)

객체의 구조(Shape)를 정의할 때 가장 많이 사용되는 두 가지 방식입니다.

* **Interface (인터페이스):** 주로 객체 자체의 구조를 정의하며, 선언 병합이나 클래스 구현, 상속(`extends`)에 유리합니다.

```typescript
interface User {
  id: number;
  name: string;
  avatarUrl?: string; // 선택적 프로퍼티 (Optional)
}

// interface 확장
interface ActiveUser extends User {
  role: "host" | "guest" | "viewer"; // 유니온 타입 지정을 통한 값 제한
  isSpeaking: boolean;
}

const participant: ActiveUser = {
  id: 1,
  name: "Seonyool",
  role: "host",
  isSpeaking: true
};

```

* **Type Alias (타입 별칭):** 객체뿐만 아니라 원시 타입, 유니온 타입, 튜플 등 모든 타입에 별칭을 부여할 때 유용합니다.

```typescript
type ID = string | number; // 유니온 타입 정의
type ConnectionState = "connecting" | "connected" | "disconnected";

const state: ConnectionState = "connected";

```

### ③ Generic (제네릭)

제네릭은 타입을 함수 매개변수처럼 전달받아 **재사용성**을 높이는 기법입니다. 특정 타입을 미리 고정하지 않고, 컴포넌트나 함수가 호출되는 시점에 동적으로 타입을 결정하도록 설계합니다.

```typescript
// 입력 배열의 첫 번째 요소를 반환하는 제네릭 함수
function getFirstElement<T>(arr: T[]): T {
  return arr[0];
}

const numberValue = getFirstElement<number>([10, 20, 30]); // T가 number로 결정됨
const stringValue = getFirstElement<string>(["A", "B", "C"]); // T가 string으로 결정됨

```

## 3. React + TypeScript 실전 적용 구조

React 환경에서 TypeScript를 활용할 때 가장 핵심이 되는 부분은 Props와 Hooks의 타입 설계입니다.

### ① Component Props 타입 선언

부모 컴포넌트가 자식 컴포넌트에게 전달하는 Props의 형태를 `interface`로 명확하게 규정하여 잘못된 데이터 전달을 방지합니다.

```tsx
import React from "react";

interface VideoPlayerProps {
  streamId: string;
  autoPlay?: boolean;
  onStreamEnd: (id: string) => void; // 콜백 함수 타입 정의
}

// React.FC를 활용한 컴포넌트 타입 바인딩
const VideoPlayer: React.FC<VideoPlayerProps> = ({ streamId, autoPlay = true, onStreamEnd }) => {
  return (
    <div>
      <video id={streamId} autoPlay={autoPlay} />
      <button onClick={() => onStreamEnd(streamId)}>종료</button>
    </div>
  );
};

export default VideoPlayer;

```

### ② useState Hook 제네릭 지정

기본 타입일 경우 타입을 추론하게 두면 되지만, 상태가 `null`을 허용하거나 여러 개의 복잡한 타입을 가질 때는 제네릭을 명시적으로 사용해야 합니다.

```tsx
import { useState } from "react";

// 1. 단순한 boolean 상태 (자동으로 boolean 타입 추론됨)
const [isMuted, setIsMuted] = useState(false);

// 2. null 상태를 포함한 객체 데이터 바인딩 (명시적 제네릭 지정)
const [currentUser, setCurrentUser] = useState<ActiveUser | null>(null);

```

## 4. 복습 및 심화 메모 (Stream Video SDK와의 연결고리)

이전 시간에 실증적으로 사용했던 Stream Video SDK의 API와 상태 훅 역시 내부적으로 철저하게 TypeScript를 기반으로 설계되어 있습니다.

```typescript
// SDK 내부의 실제 타입 정의 예시
export interface StreamVideoParticipant {
  userId: string;
  name: string;
  isSpeaking: boolean;
  publishedTracks: string[];
  // ...
}

```

우리가 `useCallStateHooks().useParticipants()`를 사용할 때 가져오는 참가자 리스트(`participants`)는 단순한 객체 배열이 아니라 `StreamVideoParticipant[]`라는 타입 보장을 받습니다.

이 덕분에 에디터 상에서 `participant.`을 입력하는 순간 `isSpeaking`, `userId` 등의 프로퍼티들이 자동 완성되고 오타가 발생하면 즉각 붉은 줄로 경고를 주는 구조적 안정성을 얻게 됩니다. TypeScript는 현대적인 웹 및 실시간 미디어 서비스 아키텍처 구축 시, 네트워크 상의 불안정한 데이터 흐름을 가장 앞단에서 통제해 주는 중추적인 역할을 합니다.

```
