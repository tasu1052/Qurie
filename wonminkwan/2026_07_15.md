# Formatting 그리고 Linting

---

## 0. 들어가며

코드 품질을 관리하려면 **Code Formatting**과 **Code Linting**이 필요하다.

| 구분 | 역할 | 대표 도구 |
|------|------|-----------|
| **Code Formatting** | 띄어쓰기, 줄 바꿈, 따옴표 등 **시각적 스타일**을 일관되게 맞춰 가독성 향상 | Prettier |
| **Code Linting** | 코드를 **정적 분석**하여 잠재적 버그, 오류, 안티 패턴 식별 | ESLint |

일반적인 흐름:

```
Prettier → 코드 스타일 정돈 (일관성)
ESLint  → 잠재적 오류·품질 문제 집중
```

---

## 1. Prettier

- **역할**: Code Formatting — 코드의 시각적 스타일을 일관되게 맞추는 작업
- **공식 문서**: https://prettier.io/docs/options
- 프로젝트 루트에 `.prettierrc` 생성

```json
{
  "singleQuote": true,
  "semi": true,
  "trailingComma": "all",
  "useTabs": false,
  "tabWidth": 2,
  "printWidth": 80,
  "bracketSpacing": true,
  "arrowParens": "always",
  "bracketSameLine": false,
  "overrides": [
    {
      "files": "*.json",
      "options": {
        "printWidth": 100
      }
    }
  ]
}
```

### 주요 옵션 정리

| 옵션 | 값 | 설명 |
|------|-----|------|
| `singleQuote` | `true` | 문자열을 작은따옴표(`'`)로 작성 |
| `semi` | `true` | 문장 끝에 세미콜론(`;`) 추가 |
| `trailingComma` | `"all"` | 여러 줄일 때 마지막 요소 뒤 쉼표 추가 |
| `useTabs` | `false` | 탭 대신 스페이스로 들여쓰기 |
| `tabWidth` | `2` | 들여쓰기 너비 2칸 |
| `printWidth` | `80` | 한 줄 최대 길이 80자 |
| `bracketSpacing` | `true` | 객체 리터럴 중괄호 안쪽 공백 추가 |
| `arrowParens` | `"always"` | 화살표 함수 매개변수 항상 괄호로 감쌈 |
| `bracketSameLine` | `false` | JSX 닫는 꺾쇠 괄호를 다음 줄에 배치 |
| `overrides` | — | 특정 파일 패턴에 다른 설정 적용 |

> 모든 옵션을 외울 필요는 없다. **Prettier = Code Formatting 도구**라는 정의를 아는 것이 더 중요하다.

## 2. ESLint

- **역할**: Code Linting — 정적 분석으로 잠재적 버그·품질 문제·안티 패턴 식별
- **공식 문서**: https://eslint.org/docs/latest/use/configure
- 프로젝트 루트에 `eslint.config.js` 생성

```js
import js from '@eslint/js';
import globals from 'globals';
import reactHooks from 'eslint-plugin-react-hooks';
import reactRefresh from 'eslint-plugin-react-refresh';
import tseslint from 'typescript-eslint';

export default tseslint.config(
  { ignores: ['dist'] },
  {
    extends: [js.configs.recommended, ...tseslint.configs.recommended],
    files: ['**/*.{ts,tsx}'],
    languageOptions: {
      ecmaVersion: 2020,
      globals: globals.browser,
    },
    plugins: {
      'react-hooks': reactHooks,
      'react-refresh': reactRefresh,
    },
    rules: {
      ...reactHooks.configs.recommended.rules,
      'react-refresh/only-export-components': [
        'warn',
        { allowConstantExport: true },
      ],
    },
  },
);
```

### 설정 포인트

| 항목 | 내용 |
|------|------|
| `ignores` | `dist` 등 빌드 결과물 린트 제외 |
| `extends` | JS·TS 권장 규칙 확장 |
| `files` | `**/*.{ts,tsx}` 파일에만 적용 |
| `languageOptions` | ECMAScript 2020, 브라우저 전역 변수 허용 |
| `plugins` | React Hooks, React Refresh 플러그인 |
| `rules` | Hooks 권장 규칙 + 컴포넌트만 export하도록 경고 |

## 3. Husky

- **역할**: Git Hooks를 쉽게 관리하는 도구
- **공식 문서**: https://typicode.github.io/husky

### Git Hooks란?

commit, push 등 **Git 작업 전·후에 자동으로 특정 스크립트를 실행**하는 기능.

Husky를 쓰면 커밋 전에 lint·테스트를 자동 실행해 **문제 있는 코드가 저장소에 올라가는 것을 방지**할 수 있다.

```bash
# Husky 설치
npm install -D husky

# Husky 초기화 → 프로젝트 루트에 .husky 폴더 생성
npx husky init
```

`.husky/pre-commit` 파일:

```sh
#!/usr/bin/env sh
. "$(dirname -- "$0")/_/husky.sh"

npx lint-staged
```

→ `git commit` 실행 시마다 자동으로 포맷팅·린트 검사 실행

## 4. lint-staged

- **역할**: Git에 **staged 상태인 파일들에만** lint 작업 실행
- **공식 문서**: https://github.com/lint-staged/lint-staged

전체 파일이 아닌 **커밋하려는 파일만** 검사 → 시간 절약. Husky와 함께 쓰면 커밋 전 변경 파일만 자동 포맷팅·린트.

```bash
npm install -D lint-staged
```

`package.json`에 추가:

```json
{
  "lint-staged": {
    "*.{js,ts,jsx,tsx}": [
      "eslint --fix",
      "prettier --write"
    ],
    "*.{json,css,scss,less,md,html,yaml}": [
      "prettier --write"
    ]
  }
}
```

| 파일 패턴 | 실행 작업 |
|-----------|-----------|
| `*.{js,ts,jsx,tsx}` | ESLint 자동 수정 → Prettier 포맷팅 |
| `*.{json,css,scss,less,md,html,yaml}` | Prettier 포맷팅만 |

## 5. 전체 파이프라인

```
개발자가 git add → git commit
        ↓
   Husky (pre-commit hook)
        ↓
   lint-staged (staged 파일만 대상)
        ↓
   ┌─────────────────────────────────┐
   │ JS/TS 파일  → ESLint --fix      │
   │             → Prettier --write  │
   │ 기타 파일   → Prettier --write  │
   └─────────────────────────────────┘
        ↓
   문제 없으면 커밋 완료 / 있으면 커밋 차단
```

## 6. Biome (참고)

Prettier + ESLint를 **대체할 수 있는** 도구.

| 항목 | 내용 |
|------|------|
| 장점 | Prettier 대비 **35배 빠른** Performance |
| 현황 | Weekly Downloads 394만 — 적지 않지만 ESLint 아성은 아직 강함 |
| 한계 | Rust 기반 → JS 개발자의 오픈소스 기여 진입 장벽, 성장 속도 제한 가능 |

→ Biome 이해가 Prettier·ESLint 이해를 더 견고하게 할 수 있음. 생태계 성장 시 다루어 볼 예정.

## 7. 핵심 정리

| 도구 | 역할 | 시점 |
|------|------|------|
| **Prettier** | Code Formatting (스타일 통일) | lint-staged에서 실행 |
| **ESLint** | Code Linting (오류·품질 검사) | lint-staged에서 실행 |
| **Husky** | Git Hook 관리 (pre-commit) | 커밋 시점 |
| **lint-staged** | staged 파일만 대상으로 lint | Husky와 연동 |

```
코드 작성
 └── git commit
      └── Husky (pre-commit)
           └── lint-staged
                ├── ESLint --fix  (JS/TS)
                └── Prettier --write (전체)
```
