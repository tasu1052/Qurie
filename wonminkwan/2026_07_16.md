# DNS 톺아보기

---

## 0. 들어가며

인터넷을 이해할 때 핵심 요소는 **라우터(Router)**와 **DNS(Domain Name System)**다.

서비스를 배포하려면, 내가 만든 프로젝트를 인터넷에 올려 누구나 접속할 수 있게 해야 한다. 유튜브·인스타그램처럼 사용자가 내 서비스에 접속하려면 **DNS의 역할**을 이해하는 것이 필수다.

| 개념 | 비유 |
|------|------|
| IP 주소 | 전화번호 (`142.250.207.14`) |
| 도메인 | 이름 (`www.google.com`) |
| DNS | 전화번호부 — 이름으로 번호를 찾아 연결 |

---

## 1. DNS 정의

**DNS(Domain Name System)** = 사람이 이해하기 쉬운 **도메인 이름**을 컴퓨터가 이해하는 **IP 주소**로 변환하는 시스템.

- `www.google.com` 입력 → 구글 서버 IP로 연결
- `142.250.207.14` 직접 입력해도 접속 가능 — 하지만 외우기 어렵고 비실용적
- DNS 덕분에 **기억하기 쉬운 도메인**으로 서비스에 접근 가능

---

## 2. DNS 조회 과정

`www.naver.com` 입력 시 실제로 일어나는 과정:

### 2-1. 캐시 확인 (로컬)

```
1. 브라우저 DNS 캐시 확인
2. 없으면 → OS DNS 캐시 확인
3. 있으면 → 즉시 연결 (가장 빠름)
```

### 2-2. DNS 서버 조회 (캐시에 없을 때)

| 단계 | 서버 | 동작 |
|------|------|------|
| 1 | **Local DNS** (기지국/ISP DNS) | `www.naver.com` IP 질의 |
| 2 | **Root DNS** | `.com` TLD 서버 위치 안내 |
| 3 | **TLD DNS** (`.com`) | `naver.com` DNS 서버 위치 안내 |
| 4 | **Second-level DNS** (`naver.com`) | `www.naver.com` → `222.122.195.6` 반환 |
| 5 | **Local DNS** | 결과 캐싱 후 사용자에게 전달 |

```
브라우저/OS 캐시
      ↓ (없으면)
Local DNS (KT, LG, 8.8.8.8 등)
      ↓
Root DNS → TLD DNS (.com) → Second-level DNS (naver.com)
      ↓
IP 주소 반환 → 캐싱 → 웹 페이지 접속
```

> Local DNS가 여러 DNS 서버에 차례로 요청해 최종 IP를 찾는 과정 = **재귀적 쿼리(Recursive Query)**

### Local DNS 서버

- ISP(KT, LG, SK) DNS 또는 사용자 지정 DNS (예: Google Public DNS `8.8.8.8`)
- **내 컴퓨터가 설정한 가장 가까운 DNS 서버** = Local DNS
- 캐시에 IP가 있으면 Root DNS까지 가지 않고 바로 응답

## 3. DNS 서버 계층 구조

DNS는 단일 서버가 아니라 **전 세계에 분산된 계층 구조**. 한 곳 장애가 전체를 멈추지 않음.

### 3-1. Local DNS Server (기지국 DNS)

| 항목 | 내용 |
|------|------|
| 역할 | 사용자 ↔ 전 세계 DNS 시스템 **중개자** |
| 핵심 기능 | **캐싱** — 인기 사이트 IP 미리 저장 |
| 캐시 없을 때 | 재귀적 쿼리 수행 (사용자 대신 다른 서버에 질의) |

### 3-2. Root DNS Server

- DNS 계층 **최상위** — 모든 도메인 질의의 출발점
- 전 세계 **13개** (A~M) + 각각 수백 개 미러 → 실질 수천 개
- **IP를 직접 주지 않음** → TLD 서버 위치만 안내 (길잡이)
- 99.9% 이상 가용성

### 3-3. TLD Server (Top-Level Domain)

Root DNS 바로 아래, **1단계 도메인** 관리.

| 유형 | 예시 | 설명 |
|------|------|------|
| **gTLD** (일반) | `.com`, `.org`, `.net`, `.edu`, `.app` | 상업·비영리·교육 등 |
| **ccTLD** (국가) | `.kr`, `.jp`, `.cn`, `.us` | 각 국가 정부/기관 관리 |

- 해당 TLD 하위 **Second-level DNS 서버 위치** 관리
- 도메인 등록·갱신·삭제 처리

### 3-4. Second-level DNS Server

- 특정 도메인에 대한 **권한(Authoritative)** 보유
- `"naver.com의 IP는 223.130.195.200"` — **최종 확답**을 주는 서버
- 서브도메인(`mail.naver.com`, `blog.naver.com` 등) 정보도 관리
- 대부분 전문 DNS 호스팅 업체에 위임

#### 주요 DNS 레코드

| 레코드 | 역할 |
|--------|------|
| **A** | 도메인 → IPv4 주소 매핑 |
| **AAAA** | 도메인 → IPv6 주소 매핑 |
| **CNAME** | 도메인 → 다른 도메인 별칭 (`www` → 메인 도메인) |
| **MX** | 메일 서버 정보 |
| **NS** | 네임서버 정보 |
| **TXT** | SPF, DKIM 등 텍스트 정보 |

### 3-5. Sub DNS Server

- **서브도메인** 전담 관리 (`mail.naver.com`, `blog.naver.com` 등)
- Second-level DNS에서 **위임(Delegation)**
- 서비스팀별 독립 관리, CDN·로드밸런싱 분리에 활용

## 4. 배포와 DNS

서비스 배포 시 DNS 설정은 **필수**. 도메인 없이는 사용자가 접속할 수 없다.

### 배포 흐름

```
1. 도메인 구입 (가비아, 후이즈, GoDaddy 등)
   └── 이름만 예약 — 서버 연결은 별도 설정

2. DNS 서버 설정
   ├── 등록업체 네임서버 → DNS 호스팅 업체로 변경
   │    (Cloudflare, Route 53, CloudDNS 등)
   └── A 레코드: 도메인 ↔ 서버 IP 연결
       CNAME: www → 메인 도메인

3. SSL 인증서 적용 (HTTPS)
   └── Let's Encrypt(무료) 또는 유료 인증서
```

### DNS 설정 시 고려사항

| 항목 | 설명 |
|------|------|
| **TTL** (Time To Live) | DNS 레코드 캐시 유지 시간 — 길면 변경 반영 느림, 짧으면 조회 빈번 |
| **CDN** | 전 세계 사용자 빠른 접속을 위한 DNS 최적화 |
| **로드밸런서** | 여러 서버 IP 설정으로 트래픽 분산 |

---

## 5. 핵심 정리

```
사용자: www.naver.com 입력
        ↓
[캐시] 브라우저 → OS → Local DNS
        ↓ (캐시 miss)
[조회] Root DNS → TLD (.com) → Second-level (naver.com)
        ↓
IP 반환 → 캐싱 → 서버 연결
```

| DNS 서버 | 역할 | 비유 |
|----------|------|------|
| Local DNS | 캐싱 + 재귀적 쿼리 | 가까운 도서관 사서 |
| Root DNS | TLD 서버 위치 안내 | 최상위 안내 데스크 |
| TLD DNS | Second-level 서버 위치 안내 | `.com` 구역 관리소 |
| Second-level DNS | 도메인 ↔ IP 최종 매핑 | 해당 도메인 담당자 |
| Sub DNS | 서브도메인 관리 | 부서별 담당자 |

DNS는 인터넷 핵심 인프라. 복잡한 IP 대신 기억하기 쉬운 도메인을 쓰고, 전 세계 어디서든 빠르게 접속할 수 있는 것은 **분산 구조 + 캐싱** 덕분이다. 배포 시 DNS를 제대로 설정해야 사용자 경험과 서비스 안정성이 보장된다.
